## 任务目标

将原本使用 eventBus 分散管理的弹窗系统重构为统一的弹窗管理器，实现：
1. 不使用 eventBus 显示弹窗
2. 弹窗分为消息弹窗和功能弹窗两种类型
3. 使用 add 等方法直接传递组件实现松耦合

## 实现要点

### 弹窗类型设计

| 类型 | 遮罩样式 | ESC 关闭 | 自动关闭 | 事件阻塞 |
|------|----------|----------|----------|----------|
| **消息弹窗** | `bg-black/20` 半透明 | 否 | 可选（autoClose ms） | 否 |
| **功能弹窗** | `bg-black/40 backdrop-blur-[2px]` | 是 | 否 | 是 |

### ModalConfig 接口

```typescript
interface ModalConfig {
  id?: string                    // 可选，不提供则自动生成
  type: 'message' | 'function'   // 弹窗类型
  component: any                 // 弹窗组件
  props?: Record<string, unknown> // 传递给组件的 props
  autoClose?: number             // 消息弹窗自动关闭时间(ms)
  closable?: boolean             // 是否显示关闭按钮
  onClosed?: () => void          // 关闭回调
}
```

### 核心 API

```typescript
// 添加弹窗
function addModal(config: ModalConfig): string

// 关闭指定弹窗
function removeModal(id: string): void

// 关闭所有弹窗
function clearAllModals(): void

// 获取顶部功能弹窗（用于 ESC 关闭）
function getTopFunctionModal(): ModalInstance | undefined
```

### 组件解耦规范

弹窗内容组件需要遵循：
1. 不包含 `visible` prop（由 ModalManager 管理）
2. 不包含 `v-if` 条件渲染（由 ModalManager 管理）
3. 通过 `emit('close')` 通知关闭
4. 不包含外层遮罩层（由 ModalManager 提供）
5. 仅关注自身内容和交互逻辑

### 事件桥接

ModalManager 拦截子组件事件并转换为相应的弹窗操作：
- `@close` -> `removeModal(id)`
- `@select-user` -> 关闭当前弹窗，打开新用户资料弹窗
- `@follow-success` -> 关闭用户资料弹窗，显示关注结果消息弹窗

## 问题解决方案

### 问题 1: handleFollowSuccess 动态组件 props 传递错误

**描述**: ModalManager 中关注成功显示的动态组件模板使用了 `v-if="isFollowing"` 但 props 定义不完整。

**修复**: 
```typescript
// 修复前
props: { isFollowing: Boolean }

// 修复后  
props: { isFollowing: { type: Boolean, default: false } }
template: '<span :class="isFollowing ? \'text-[#4df0ff]\' : \'text-[#4df0ff]/60\'">{{ isFollowing ? \'关注成功\' : \'已取消关注\' }}</span>'
```

### 问题 2: HoloUserProfile 残留 eventBus import

**描述**: HoloUserProfile.vue 中仍导入但未使用 eventBus。

**修复**: 移除未使用的 `import { eventBus } from '@/utils/eventBus';`

## 兼容性说明

### 保持现有 eventBus 的组件

以下组件仍使用 eventBus 消息系统，保持兼容：

| 组件 | 原因 |
|------|------|
| `HoloDanmaku.vue` | 弹幕系统：高频、自动消失、不阻塞交互，与弹窗系统职责不同 |
| `LoginPanel.vue` | 登录消息提示，使用弹幕显示，保持现有机制 |

### 消息系统对比

| 系统 | 适用场景 | 特点 |
|------|----------|------|
| **弹窗系统** | 低频、需要交互、可能阻塞 | 栈管理、ESC 关闭、事件阻塞 |
| **弹幕系统** | 高频、自动消失、不阻塞 | 队列显示、自动移除、不影响交互 |
